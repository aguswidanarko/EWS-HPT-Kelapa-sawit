# Format Import Nyata — "REKAP HPT PISP1" (contoh dari user)

User melampirkan file Excel produksi nyata: `docs/samples/REKAP_HPT_PISP1_2026.xlsx` (15 sheet) sebagai **contoh data deteksi/sensus yang akan diupload lewat web dashboard**. Ini BUKAN format template flat generik yang sudah dibuat backend sebelumnya (satu baris = satu observasi) — ini adalah **rekap bulanan berbentuk pivot per Blok** (satu baris = satu Blok, kolom-kolom = bulan/periode), format standar yang sudah dipakai kebun PISP1 di lapangan. Fitur "Import Data" di dashboard harus bisa menerima file asli ini, bukan memaksa user mengubah formatnya.

Nilai di sebagian besar sel contoh ini = 0 atau kosong (kolom master Afdeling/Blok/Ha/Tahun Tanam terisi nyata, kolom hasil bulanan belum diisi untuk tahun berjalan) — jadi ini adalah **template rekap tahunan kosong**, representatif struktur, bukan data serangan nyata. Importer harus tetap benar menangani ini (skip bulan yang kosong/nol, tidak membuat record sensus palsu untuk sel kosong).

## Sheet yang RELEVAN dengan BRD (harus didukung importer)

1. **`REKAP SNS UPDKS`** — Header baris 5-7 (merged). Kolom dasar: `Afdeling, Block, Jenis Tanah, Ha, Tahun Tanam` lalu kolom "Hasil Sensus Rata Ulat per pelepah" per periode: `2025/TW4` lalu 12 kolom bulan `Jan..Des` untuk tahun berjalan (2026). Setiap sel bulan = rata-rata ulat/pelepah untuk Blok itu pada bulan itu → satu record SENSUS jenis UPDKS per (blok, bulan) jika selnya terisi dan bukan kosong. Ada juga blok "PETA SENSUS UPDKS <BULAN>-2026" di sebelah kanan (kolom baris-sampel individual B21/C21/D21 dst) — ini adalah **breakdown per baris sampel** untuk bulan tersebut, opsional untuk parsing detail (nice-to-have); minimum wajib: ambil rata-rata per blok per bulan dari kolom Jan-Des.
2. **`REKAP SNS TIKUS`** — sama persis strukturnya dengan UPDKS di atas, tapi nilainya "% Serangan Baru Hama Tikus". Kolom dasar: `Afdeling, Block, Jenis Tanah, Ha, TT (tahun tanam)`.
3. **`SNSS ORYCTES`** — Header baris 7-8 (merged), dua blok bulan berdampingan (mis. "BULAN JULI 2026" dan "BULAN AGUSTUS 2026" — setiap file punya kolom-bulan yang berbeda tergantung periode terakhir diisi, JANGAN hard-code nama bulan, baca dari header row 6). Kolom dasar: `No, Afd, Blok, Luas, Tanggal, Jumlah Sampel`. Untuk tiap blok-bulan: pasangan kolom `Serangan Baru (Jumlah/%)`, `Stagnan (Jumlah/%)`, `Recovery (Jumlah/%)`, `Mati (Jumlah/%)`, `Keterangan`. → satu record SENSUS Oryctes per (blok, bulan) jika ada data.
4. **`SNSS RAYAP`** — Header baris 4-5 (merged). SATU baris = SATU blok (bukan pivot bulanan — sensus rayap rotasinya 2 bulan sekali, jadi sheet ini merepresentasikan rotasi TERKINI per blok). Kolom: `AREAL(TM/TBM), AFD, BLOK, TT, LUAS, PKK(jumlah pokok), SPH(pokok/ha)`, lalu grup `SENSUS`: `TGL SENSUS, SERANGAN BARU, SERANGAN RAYAP KEMBALI, POKOK MATI, TGL SEMPROT, TOTAL POKOK DISEMPROT, POKOK BARIER DISEMPROT, PKK/HA (TERSERANG)`. → satu record SENSUS Rayap per blok jika `TGL SENSUS` terisi.
5. **`SNS GANODERMA`** — mirip Rayap: satu baris = satu blok. Kolom: `AREAL, AFD, BLOK, TT, LUAS, PKK, SPH`, grup `REKAP SENSUS`: `TGL SENSUS, POKOK NORMAL, KRITERIA SERANGAN GANODERMA (S1,S2,S3,S4), PKK/HA (TERSERANG)`. S1-S4 = kategori/status serangan kualitatif (bukan rumus numerik, sesuai SPEC.md §5). → satu record SENSUS Ganoderma per blok jika `TGL SENSUS` terisi.
6. **`REKAP PENGENDALIAN TIKUS`** — pivot per blok dengan kolom kelompok "Rotasi 1..5" + "Sensus Awal" + "Sensus Sesudah Kampanye", masing-masing berisi `Tanggal, Jmlh racun (kg), % Umpan Hilang` (atau `Jmlh pkk, HK, Jmlh racun` untuk rotasi tertentu). → satu record TREATMENT (metode = "Racun Tikus") per (blok, rotasi) yang tanggalnya terisi.

Baca header sebenarnya dari file secara dinamis (row offsets bisa sedikit beda antar sheet/tahun) — JANGAN hard-code nomor kolom mentah-mentah tanpa membaca header dulu; gunakan pendekatan: cari baris header (row yang berisi label seperti "Afdeling"/"Blok"/"Jan"/dst), lalu petakan kolom by label, resilient terhadap pergeseran kolom antar file.

## Sheet YANG SAAT INI DI LUAR SCOPE BRD (jangan diimplementasikan sekarang, cukup dicatat)

- `Rekap ESTATE UPDKS`, `Rekap ESTATE TIKUS`, `REKAP P UPDKS PERIODE JAN/MAR` — ini laporan/peta agregat turunan (output view), bukan data input mentah. Tidak perlu diimport; dashboard sudah punya fitur reporting/peta sendiri yang menghasilkan agregat serupa dari data yang sudah masuk.
- `REKAP SNS KBH`, `REKAP SNS KBH (2)`, `REKAP KBH` — monitoring perangkap "KBH" (kumbang/predator alami, kemungkinan terkait pengendalian hayati Oryctes: jumlah terpasang, aktif/tidak aktif, tahap dewasa/anak/telur). Ini KATEGORI HPT/monitoring BARU yang tidak ada di BRD manapun (bukan salah satu dari 5 HPT: UPDKS/Tikus/Oryctes/Rayap/Ganoderma). Jangan dibangun sekarang — catat sebagai temuan gap requirement untuk didiskusikan dengan user, karena akan butuh entitas & threshold baru di luar cakupan BRD saat ini.
- `BENEFICIAL PLANT` (2 sheet) — pemantauan tanaman inang musuh alami (pengendalian hayati). Juga di luar cakupan 5 HPT BRD. Catat sebagai gap yang sama, jangan diimplementasikan sekarang.

## Yang harus dibangun

1. **Backend**: `backend/src/services/importPisp1.js` — parser dinamis per sheet di atas (6 sheet relevan) yang menghasilkan array record ternormalisasi (jenis_sensus/treatment, estate, afdeling, blok — auto-resolve/auto-create Blok master dari Afdeling+Blok+Ha+Tahun Tanam bila belum ada, tanggal, hasil, dst), melewati pipeline threshold/incident engine yang SUDAH ADA (jangan bikin ulang, reuse `thresholdEngine`/`sensusEngines`/`ingestion` services yang sudah dibangun backend agent sebelumnya — baca kode itu dulu di `backend/src/services/`). Endpoint baru: `POST /api/import/pisp1/preview` (upload file, kembalikan ringkasan per sheet: jumlah baris terbaca, jumlah data valid akan dibuat per HPT, jumlah dilewati karena kosong, error list) dan `POST /api/import/pisp1/commit` (confirm eksplisit, sama seperti alur import Excel BRD 02 §28 — tidak boleh partial import tanpa konfirmasi). Skip sel kosong/nol dengan aman (bukan error, cukup "dilewati — tidak ada data").
2. **Dashboard**: tambahkan opsi di halaman Import Data: "Import Rekap Bulanan (Format PISP1)" — upload → preview per-sheet (mirip preview Excel yang sudah ada, tapi dikelompokkan per sheet/HPT) → tombol konfirmasi commit.
3. **Verifikasi WAJIB terhadap file asli**: jalankan importer terhadap `docs/samples/REKAP_HPT_PISP1_2026.xlsx` yang sebenarnya (bukan file buatan sendiri), pastikan: parsing tidak error, jumlah Blok yang terdeteksi/dibuat masuk akal, sel kosong/nol dilewati tanpa membuat record sampah, dan (isi manual 1-2 sel dummy dengan angka yang melewati threshold di salinan file test untuk membuktikan record+incident+alert benar-benar terbentuk end-to-end — JANGAN modifikasi file asli di `docs/samples/`, buat salinan test terpisah).
